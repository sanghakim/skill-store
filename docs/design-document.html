01Executive Summary

본 문서는 SkillForge 멀티 에이전트 시스템의 기술 설계를 정의합니다. SkillForge는 단일 AI 챗봇의 한계를 넘어, 전문화된 에이전트 팀이 협업하여 복잡한 업무를 자율적으로 처리하는 차세대 AI 플랫폼입니다.

Core Innovation

Agentic Loop 아키텍처 + 확장 가능한 Skill 시스템 + 커뮤니티 기반 Skill Store를 결합하여, 사용자가 코딩 없이 AI 능력을 무한히 확장할 수 있는 플랫폼을 구축합니다.

Key Design Decisions

DecisionChoiceRationale
Architecture PatternOrchestrator + Worker Pool유연한 스케일링, 에이전트 독립 배포
Agent CommunicationShared Context Bus (Pub/Sub)비동기 병렬 처리, 느슨한 결합
Memory Model3-Layer (Working/Episodic/Semantic)단기-장기 기억 분리, 효율적 컨텍스트 관리
Skill DefinitionYAML Schema + Prompt Template비개발자 접근성, 버전 관리 용이
Skill ExecutionSandboxed Runtime보안 격리, 장애 전파 방지

04Agent Design

4.1 Agent Types & Roles

AgentRolePrimary SkillsTrigger Condition
Planner 복잡한 작업을 하위 작업으로 분해하고 실행 계획(DAG)을 수립 task-decomposer, dependency-resolver 복합 의도 감지 시 (2+ sub-tasks)
Executor 개별 스킬을 호출하여 실제 작업을 수행 All registered skills 실행 가능한 단위 작업 배정 시
Reviewer Executor 결과를 검증하고 품질 기준 충족 여부를 판정 validator, fact-checker, quality-scorer Executor 완료 후 자동 실행
Research 정보 수집, 문서 분석, 데이터 검색을 수행 web-search, doc-parser, data-fetcher 정보 부족 또는 검증 필요 시
Creative 콘텐츠 생성, 아이디어 발상, 창작 작업을 수행 text-generator, template-engine, brainstormer 생성형 작업 감지 시

05Agentic Loop

5.1 Loop Architecture

Agentic Loop는 시스템의 핵심 실행 패턴으로, 에이전트가 자율적으로 계획-실행-검증을 반복하여 최적의 결과를 도출합니다.

                    User Input
                        |
                        v
              +-------------------+
              |  Intent Analysis  |
              |  (Orchestrator)   |
              +--------+----------+
                       |
                       v
              +-------------------+
              |  Plan Generation  |  <--- Planner Agent
              |  (Task DAG)       |
              +--------+----------+
                       |
           +-----------+-----------+
           |                       |
           v                       v
  +----------------+     +----------------+
  | Parallel Task  |     | Parallel Task  |  <--- Executor Agents
  |   Execution    |     |   Execution    |       (with Skills)
  +-------+--------+     +-------+--------+
          |                       |
          +-----------+-----------+
                      |
                      v
            +-------------------+
            |  Quality Review   |  <--- Reviewer Agent
            |  (Validation)     |
            +--------+----------+
                     |
              +------+------+
              |             |
         [PASS]         [FAIL]
              |             |
              v             v
     +-----------+  +--------------+
     |  Response |  |   Re-plan &  | ----> (Back to Plan Generation)
     |  Assembly |  |   Re-execute |       Max 3 iterations
     +-----+-----+  +--------------+
           |
           v
      User Output

5.3 Execution Example

Scenario: "지난달 매출 데이터로 임원 보고서 만들어줘"


Iteration 1:
1. Orchestrator: 3개 하위 작업으로 분해
2. Research Agent: excel-analyzer 스킬로 매출 데이터 분석
3. Creative Agent: doc-drafter 스킬로 보고서 초안 작성
4. Reviewer Agent: 수치 불일치 2건 발견 → FAIL (score: 0.72)

Iteration 2:
5. Executor Agent: 수치 교정 후 재작성
6. Reviewer Agent: PASS (score: 0.93)
7. Result Merger: 최종 보고서 + 발표 노트 통합 출력

06Memory & Context Management

6.1 Three-Layer Memory Architecture

LayerTTLStorageContentAccess Pattern
Working Memory Session Redis 현재 대화, 에이전트 상태, 실행 중 스킬 스택 Read/Write per turn
Episodic Memory Persistent PostgreSQL 과거 세션 요약, 작업 이력, 사용 패턴 Write per session, Read on-demand
Semantic Memory Permanent Vector DB 사용자 선호, 도메인 지식, 스킬 메타데이터 RAG retrieval per query

07Skill Execution Engine

7.1 Skill Lifecycle

Define (YAML) → Validate → Test → Publish → Register → Load → Execute → Monitor

7.2 Execution Pipeline

# Skill Execution Pipeline (Pseudocode)

def execute_skill(skill_id, inputs, context):
    # 1. Load skill definition from Registry
    skill = registry.load(skill_id)

    # 2. Validate inputs against schema
    validated = schema_validator.validate(inputs, skill.input_schema)

    # 3. Resolve prompt template with variables
    prompt = template_engine.resolve(skill.prompt_template, validated)

    # 4. Inject context (user preferences, history)
    prompt = context_injector.enrich(prompt, context)

    # 5. Execute in sandbox with resource limits
    result = sandbox.execute(
        prompt = prompt,
        model = skill.settings.model,
        max_tokens = skill.settings.max_tokens,
        temperature = skill.settings.temperature,
        timeout_ms = skill.settings.timeout_ms
    )

    # 6. Validate output against schema
    output = schema_validator.validate_output(result, skill.output_schema)

    # 7. Log execution metrics
    metrics.log(skill_id, tokens=result.tokens, latency=result.latency)

    return output

08Skill Schema Specification

8.1 Complete Schema Definition

# SkillForge Skill Definition Schema v1.0

skill:
  id: "email-composer"            # Unique, lowercase, hyphens
  name: "Business Email Composer"   # Display name
  version: "2.0.0"                  # Semantic versioning
  author: "user-001"
  category: "email"                  # Predefined categories
  description: "Compose business emails with appropriate tone"
  icon: "email"

  inputs:
    - name: "context"
      type: "string"
      required: true
      description: "Email situation description"
    - name: "tone"
      type: "enum"
      values: ["formal", "friendly", "urgent", "apologetic"]
      default: "formal"

  outputs:
    - name: "subject"
      type: "string"
    - name: "body"
      type: "string"

  prompt_template: |
    You are a business email expert.
    Situation: {{context}}
    Tone: {{tone}}
    Write a professional email.

  settings:
    max_tokens: 2000
    temperature: 0.7
    model: "default"
    requires_review: true

  permissions:
    - "read:user_context"
    - "write:clipboard"

  tags: ["email", "business", "communication"]

11.2 Skill Review Policy

  1. Automated Scan: 프롬프트 인젝션, 유해 콘텐츠 자동 탐지
  2. Schema Validation: 필수 필드, 타입, 권한 선언 검증
